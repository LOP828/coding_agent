# Coding Agent M3 — Codex 开发任务说明

> 状态：MK 已确认的 M3 需求；本文件是开发约束，不是已完成或已实测报告。
> 目标仓库：`D:\project\coding_agent`（WSL：`/mnt/d/project/coding_agent`），独立于其他项目；拟放置路径：`docs/M3/Coding_Agent_M3_Codex_Task.md`。

## 一、背景与本轮目标

- M0：`src/coding_agent/m0.py` 已提供数据契约与确定性判定；M1：Runner 自主从 Git/文件快照取证，在干净目录验证并生成报告；M2：候选代码与判定进程隔离，Codex + GPT-6 Luna 完成 provider 校验并由独立 Runner 判定 PASS（以上为 MK 提供的既有进展）。
- M3 只建立**确定性的开发控制层任务地图**：所有工作挂在地图节点上；执行发现先暂存，不能自动扩大范围；子任务完成焦点返回父节点；节点可追溯至冻结需求。
- 本轮不实现整张地图的自动调度；原子任务仍由 MK 逐个触发。

## 二、开工门禁及工作顺序（必须遵守）

1. 确认当前仓库、分支、工作区和既有 M0/M1/M2 测试基线；不进入或修改其他项目仓库。
2. **先仅把本任务说明提交一次**至 `docs/M3/Coding_Agent_M3_Codex_Task.md`，提交说明写为 `M3 需求，MK 已确认`；此后不得修改本文件。不要把无关改动混入该提交。
3. **随后只提交文字执行计划**：列出准备创建/修改的完整文件清单、状态转换表、焦点进入与返回规则、暂存区 Schema、任务地图及不可改历史记录的存放路径、需求追溯数据来源，以及 Codex 只读沙箱写入失败的实测方法。
4. 向 MK 展示计划，**暂停并等待明确批准后才能写代码**；未获批准不得实施或自行补充未定规则。真实规划调用还须按第五节单独批准提示词与参数。
5. 批准后分步实现、测试、保存证据并在本独立仓库本地提交；**不得 push**。

## 三、强制架构约束（M3 起）

- **控制层只能是确定性程序**：同样的结构化输入、既有状态和固定规则得到同样的状态/判定；时间戳仅用于审计，不参与规则判断。禁止借助 AI 理解自由文本后决定状态、准入、焦点或权限。
- **规划、审查等 AI 模块只能只读运行**，产出符合 Schema 的结构化提案；控制层仅做结构/格式验证及固定规则检查，不将 AI 的自述视为批准或 PASS。
- **只有 Executor 能按任务卡白名单修改代码**；控制层代码与状态文件始终属于任务卡自动保护的禁止修改路径。任务运行中任何 AI 都不得修改控制层，控制层自身变更需 MK 确认。
- 不更改 `m0.py` 的判定规则、任何已有 Schema、冻结夹具、既有归档证据；M3 需要的新数据格式另建 Schema，保留 M0/M1/M2 原有测试。

## 四、开发需求与完成条件

### R-M3-01 任务地图与不可改历史

- 定义新的任务地图 Schema。每个节点至少有：唯一编号、父节点编号、标题、`requirement_refs`、类型（阶段/原子任务）、状态、创建来源（MK 直接创建 / AI 提案经 MK 批准）。节点父子关系及引用须按规则验证。
- 只有控制层能落盘修改地图；每次变更追加审计事件，记录**谁、何时、变更前后/具体改动、依据**；历史仅追加、不覆盖、不删除。AI 提案不等于地图变更。
- 文件布局和写入入口在开工计划中列清，证明 Executor/只读 AI 均不能直接改地图或审计记录。

### R-M3-02 固定状态机与焦点管理

- 至少支持 `PENDING / READY / RUNNING / DONE / BLOCKED / DEFERRED`；以**显式允许转换表**为唯一准入规则，未列出的转换拒绝并保留原状态。完整转换矩阵必须先交 MK 审核，不得自行添加隐式捷径。
- 同一时刻最多一个**原子任务**处于 `RUNNING`，其为执行焦点；其余执行请求必须服从焦点/授权规则。
- 原子任务 `DONE` 的唯一有效证据是**独立 M1/M2 Runner 的 PASS**；Executor、AI 提案、人工文字报告都不得直接宣告 `DONE`。
- 子任务 `DONE` 后焦点自动回到父节点；不自动跳到兄弟节点。当前焦点未结束，未经 MK 明确切换的兄弟节点跳转须拒绝；原子任务依然只能由 MK 明确触发。
- 阶段/父节点仅当所有子节点 `DONE` 或被 **MK 明确**设为 `DEFERRED` 后才允许 `DONE`；不得把 AI 建议延期当作 MK 批准。

### R-M3-03 发现暂存区（Deferred Findings）

- 执行或规划发现的新问题/想法，只能作为暂存区条目保存；不可自动加入地图、生成新任务、改变焦点或触发执行。
- 定义暂存区条目及 Executor 发现消息的结构化格式（至少关联来源任务、发现内容、提交来源和可追溯证据）。优先使用**当前 Codex 实际支持**的结构化输出；不支持则要求最终消息包含规定格式的 JSON 代码块。
- 控制层只按格式解析、校验和归档；解析失败时原文存档，**不作处理、不猜测意图**。仅 MK 有权提升为节点或删除；审批动作由控制层按规则实施并记入历史。

### R-M3-04 冻结需求追溯与结构覆盖

- 每个节点必须引用已冻结的需求 ID；复用 M0 的 `EXPLICIT / DERIVED / UNSOURCED` 规则及有效追溯关系；`UNSOURCED` 拒绝进入地图。不得擅改 M0 语义或判定。
- 对所有冻结需求做**结构覆盖检查**：至少被一个有效节点引用，或由 MK 明确延期；未覆盖的需求逐条列入状态报告。
- 覆盖仅表示 ID/引用关系成立，**不声称理解或验证语义覆盖**；AI 的“已覆盖”文字不能替代结构检查。

### R-M3-05 只读 AI 规划提案与一次真实演示

- 规划器以 Codex **只读沙箱**接收冻结需求和当前地图，只能输出 Schema 提案：新增节点及原子任务卡草稿；没有直接写地图、写代码、批准或执行的能力。
- 先在实际所用 Codex 版本和启动参数下尝试写文件，确认**写操作真实失败**并保存命令、版本、退出码、前后文件状态等证据；不能仅凭文档/源码推断只读有效。
- 控制层格式和固定规则校验通过的提案进入“**待 MK 批准**”，批准前不生效；校验失败不得入图。MK 批准后由控制层写地图并记录事件。
- 用一项小型冻结需求进行一次**真实规划**，目标拆成 2–3 个原子任务。真实模型调用**最多 5 次（含失败尝试与重试）**；默认 `GPT-6 Sol`、`medium`，实际 CLI 模型标识以可用版本核验为准。
- **调用前单独暂停**，向 MK 展示完整提示词、模型/推理强度、沙箱配置、命令及预计调用次数，获准后才执行。真实调用不进入默认 `pytest`，单独命令运行并存证；只报告本次观察，不做可靠性/成功率推断。

### R-M3-06 权限约束可执行、可测试

- 每张原子任务卡的受保护路径必须自动包含控制层自身代码与任务地图/状态/审计文件；不得仅依赖提示词约束，沿用已有 Runner 的越权变更检测能力。
- 规划、审查模块的调用入口只允许只读权限；代码中不得有以可写权限调用这些 AI 模块的路径。用自动化测试验证权限构造和拒绝逻辑，并结合 R-M3-05 的真实只读写入失败证据。

### R-M3-07 MK 可读状态报告

- 控制层生成纯文本或 Markdown 报告，至少列出：主线/目标、当前焦点、各节点状态、暂存区、待 MK 决策事项、未覆盖冻结需求；数据必须来自控制层记录，不以模型自由文本重新判断。
- 不做 GUI，也不把报告生成视作完成任务或授权切换。

## 五、验收与证据

1. **跨平台**：分别在 Windows 原生中文 CP936 环境（`git core.autocrlf=true`，不设置 `PYTHONUTF8`）及 Linux 运行 `python -m pytest`；分别列明 `passed / failed / errors / skipped`。M0/M1/M2 原有测试全部保留；新增功能测试并入默认测试集。
2. **纯脚本演示，不调模型**：从有父子关系的任务地图开始，MK 明确触发一个原子任务 → Executor 结构化提交一条发现进入暂存区 → 使用真实 Runner 的 PASS 证据使该子任务 `DONE` → 焦点回父节点 → 未经 MK 切换直接请求兄弟节点被拒 → 报告列出未覆盖的冻结需求。不得伪造 Runner PASS 替代验证。
3. **负例与权限**：拒绝非法状态转换、双 `RUNNING`、无 Runner PASS 的原子任务 `DONE`、未批准提案入图、未授权提升暂存条目、`UNSOURCED` 节点、越权路径修改、只读 AI 可写入口。
4. **真实规划单独执行**：记录 MK 批准、输入、准确启动参数、模型调用次数、原始响应、结构化校验结果、沙箱写入测试及完整证据路径；未执行项目不可写成“已实测”。
5. 提供一份本轮实际结果摘要：文件变更、跨平台测试数字、脚本演示、真实运行/未运行情况及限制、审计记录样本、本地提交 ID；不写虚构的成功率。证据存档不覆盖既有归档。

## 八、MK 补充（优先于前文）

1. 状态转换原则（完整矩阵仍由 Codex 在计划中给出，MK 审核）：
   - BLOCKED 恢复为 READY、设置或撤销 DEFERRED，只能由 MK 发起。

2. 焦点规则：子任务 DONE 后焦点回到父节点。下一个原子任务必须由 MK 用明确命令启动，且只能是当前焦点节点的子节点；跳到其他分支需要 MK 单独的“切换焦点”命令，并记入历史。
