# Coding Agent M1：控制层自主取证（Codex 开发任务）

## 一、目标与边界
- 本任务依据 MK 已确认的 M1 需求实施：把 M0 中由报告提供的“实际变更清单”和“测试执行结果”改为控制层自主取得。
- **不修改 `src/coding_agent/m0.py` 的判定规则**；继续调用既有 `aggregate_gate`，不得另写一套 gate。
- 必须在 **Coding Agent 独立仓库**工作。开工先检查实际工作目录与 Git 根目录；若落在 `self_media_agent`、`topic_agent`、`creator_data_collector`、`cnc-programmer` 或其他项目仓库，立即停止并报告。新目录尚未初始化 Git 时，可在确认它是 Coding Agent 专用目录后初始化。
- 不沿用其他项目的 `codex/core-dev` 分支、`scripts/core_tests.py` 或四项自媒体验收命令；本项目以 `python -m pytest` 验收。
- Executor 继续由预先写好的候选代码模拟；不接 AI、Codex harness、调度、容器或系统沙箱，也不实现网络隔离。
- 优先复用 M0 代码、契约及既有四个场景；除 R-M1-05 所列作弊样本外，不另造新的业务样本。

## 二、功能实现
### R-M1-01｜真实 Git 变更清单
- Runner 在模拟执行**之前**记录任务开始时的版本/工作区基线，在执行**之后**依据真实 Git 状态和文件变化生成实际路径清单；不能用 Executor/报告传来的 `changed_paths`。起点存在未提交改动则直接拒绝启动。
- 必须覆盖修改、新增、删除、重命名、未跟踪新文件；重命名应保留源路径和目标路径，以便越权判断。还必须对 Git 忽略的候选路径做前后差异核查，不能只依赖 `git status`。
- 仅排除明确登记的控制层自身证据目录，排除清单必须列明；路径比较与记录使用 `as_posix()`。
- **原 M0 场景 03**必须改为：Executor 实际越权改文件 → Git 比较发现路径 → 原有 M0 规则拒绝；不得靠伪造报告触发。

### R-M1-02｜干净目录中的冻结测试
- 每一次验证都创建**新的临时目录**，只复制本次候选代码；验收测试从控制层持有的冻结副本注入，不沿用候选仓库自带测试。
- 对冻结测试维护文件清单和哈希；运行前核对清单及文件哈希，任何不匹配都禁止执行并记录原因。
- 候选代码中与控制层测试同名的文件必须由控制层副本覆盖，绝不能被收集或执行为验收依据。
- 采取必要的 pytest 启动与收集约束，使候选的测试配置/插件注入样本无法篡改验收；不得声称临时目录提供安全隔离。

### R-M1-03｜Runner 生成 VerificationReport
- Runner 执行真实 pytest 验证，读取该次运行生成的 **JUnit XML**，按既有字段契约生成 `VerificationReport`；不能采信候选代码自行声明的测试数量/测试结论。
- `test_count` 只计算实际执行且未跳过的用例；必需测试若 skipped，记为 `NOT_RUN`，gate 为 `BLOCKED`；XML 缺失、损坏或无法解析必须显式失败/阻断。
- 验证完成后，使用 M0 的 `aggregate_gate` 聚合；不改变 M0 原有判定语义。

### R-M1-04｜先准入，后执行
- 串接真实入口：先按 M0 现有契约检查准入状态及内容/授权，再决定是否允许 Runner 启动任何候选代码。
- 对 `PENDING`、`REJECTED`、任务内容被改、未授权扩权，必须**零次执行**：不得启动候选进程、导入候选模块或运行候选测试。
- 用真正经过 Runner 入口的测试和可核对的零执行证据，替换 M0 那项仅形式化断言的测试；保持 M0 已有测试覆盖不退化。

### R-M1-05｜防作弊样本
- 在 M0 四个场景之外，仅新增下列样本；分别证明被**阻断或失效**，并检查 Runner 最终证据：
  1. 候选修改/替换验收测试文件；
  2. 候选新增 `conftest.py` 干预 pytest；
  3. 候选新增 `pytest.ini`、`pyproject.toml`、`setup.cfg` 改变测试配置；
  4. 候选新增 `sitecustomize.py` 或 `.pth` 在 Python 启动时注入代码；
  5. 候选向 Runner 验收 Python 环境的 `site-packages`（包括被忽略的 `.venv`）写入 `sitecustomize.py` 或 `.pth`。
- 第 6 类：候选代码检测“是否在测试中”并返回不同结果。**只做样本及限制记录**，明确标为“当前 M1 无法防范”；不要求拦截，也不把它写成 PASS 的防护能力。
- Runner 的验收 Python 环境须对候选不可写，或者能够检测上述环境写入并阻断；若做不到，明确记为“M1 无法防范”。不得将其包装为系统级隔离。

### R-M1-06｜M0 两项遗留修复
- 日常运行证据输出到被 `.gitignore` 忽略的目录；已提交的归档证据视为只读，日常测试不得再改写。
- `schema_root` 只保留在控制层内部；Executor 对外调用接口不可见、不可传该参数。

### R-M1-07｜Codex harness 可写路径限制调查（只写报告）
- **仅调查，不接入 harness、不写此功能代码**。识别所研究开源 Codex harness 的仓库、版本/提交及可信来源。
- 提交一页调查结论：是否支持文件级/目录级写入限制；如支持，具体配置及生效边界；如不支持，说明限制和可核实依据；区分工具层路径约束与操作系统级强制隔离。
- 如当前环境不能联网核实上游资料，**整份调查报告**标为“未证实”，不得凭记忆写确定性结论。供 M2 决策，不因此扩大 M1 范围。

## 三、验收与证据
- 除被替换的形式化准入测试外，M0 原有测试均须保留且通过；列明替换的测试名称和数量。80 项是 M0 基线，不要求替换后数量机械保持 80。新增 M1 测试加入主测试集，不放宽原断言。
- R-M1-01 的场景 03 必须使用真实 Git 比较；R-M1-02～05 的关键结论必须由实际执行/拦截记录验证，而非手工编写的成功报告。
- Windows 中文系统（CP936）、`git core.autocrlf=true`、**不设置 `PYTHONUTF8`** 下运行 `python -m pytest`；Linux 也运行同一命令。分别报告 passed、failed、errors、skipped 及跳过原因，要求 failed=0、errors=0。增加 Windows 实测：仅换行变化不应误判越权，但真实内容变化必须检出。
- 云端若无法执行 Windows 原生验证，必须标记 `PENDING_WINDOWS_VALIDATION`，不得以 Linux 通过宣称最终 PASS。
- 新增/修改的文本读写一律显式 `encoding="utf-8"`；路径记录/比较用 `as_posix()`；不写死 `/mnt/...`、`.venv/bin/python` 等平台路径；不直接依赖 `fcntl` 等单平台模块。
- 不修改 M0 冻结证据、快照、Gold 或已有哈希；如既有测试要求需调整调用入口，只做保持语义的最小迁移。
- 在当前 Coding Agent **独立仓库本地提交，不 push**；不得借用其他项目的分支约定。除必要的 R-M1-07 一页报告及运行证据外，不额外生成 README/CHANGELOG/VALIDATION 规格包。

## 四、最终交付
- 报告：提交哈希、修改文件清单、保留/替换的 M0 测试与 M1 新增测试结果、Windows/Linux 各自 `python -m pytest` 数字、场景 03 Git 证据、六类作弊样本结果、遗留问题（≤3 条）。
- 明确写出：**临时目录不是安全沙箱；恶意候选代码仍可能读取或破坏目录外文件；候选识别是否在测试中并改变行为的作弊在 M1 无法防范。**
- 不修改 M0 判定规则，不擅自做 M2 的系统级隔离、harness 接入、AI 接入或调度。

## 五、MK 确认与补充（优先于先前未定项）
1. `test_count` 计“实际执行且未跳过”的用例数，与 M0 规格一致；被跳过的必需测试按 `NOT_RUN` 处理，gate 为 `BLOCKED`。
2. 任务开始时工作区有未提交改动，Runner 拒绝开始并报告，不尝试处理脏基线。
3. 变更检测不能只依赖 `git status`。被 `.gitignore` 忽略的路径同样要检测，包括候选通过修改 `.gitignore` 隐藏的新文件；控制层自己的证据目录除外，且要单独列明。
4. 增加作弊样本：候选往 Runner 所用虚拟环境的 `site-packages` 写入 `sitecustomize.py` 或 `.pth`。要求验收 Python 环境对候选不可写，或检测此类写入并阻断；做不到就如实记录为“M1 无法防范”。检测机制不等于系统级安全沙箱。
5. Windows `core.autocrlf=true` 下，只有换行符差异的文件不得误判越权；真实内容变化必须检出，两种情况都要有测试。
6. 报告列出 M0 被替换的形式化准入测试名称及数量；除被替换项外其余 M0 测试全部保留通过。
7. R-M1-07 如当前环境无法联网查阅并核实资料，整份调查报告标为“未证实”，不得凭记忆写结论。
