# M3 状态机与控制层入口

依据已冻结的 M3 任务说明及 MK 后续确认。控制层只验证结构与固定规则，不使用模型理解文本。
MK 入口是受信任的本地操作入口；AI 提案和发现内容不能调用它，也不能用 actor="MK" 自报授权。
此约束不是对任意同用户宿主程序的身份认证。

| 当前状态 | 允许的目标状态及条件 |
|---|---|
| PENDING | READY / BLOCKED / DEFERRED：MK 命令 |
| READY | RUNNING：仅原子任务，MK 显式启动并绑定任务、焦点及真实 Runner；DONE：仅阶段且子节点条件满足，由 MK 确认；BLOCKED / DEFERRED：MK 命令 |
| RUNNING | DONE：仅控制层收到本次独立 Runner 的最终 PASS；BLOCKED：最终未通过；BLOCKED / DEFERRED：MK 停止请求在当前进程退出后生效 |
| DONE | 无，终态 |
| BLOCKED | READY / DEFERRED：MK 命令 |
| DEFERRED | PENDING：MK 撤销延期，后续另行准备就绪 |

未列出的转换和重复设置同一状态均拒绝。READY → DONE 对原子任务一律拒绝，不能用人工报告、AI 自述或导入的 PASS JSON 绕过真实 Runner。
阶段不进入 RUNNING；至少有一个子节点，且全部 DONE 或具有 MK 明确延期记录时，报告显示“可完成”；不会自动完成阶段。
延期不级联，有未完成、未明确延期子节点的阶段不能整体延期。完成节点不重开、不追加子节点。

**M2 的单次重试属于同一次 RUNNING。** 首次 EXECUTION_FAIL 只在运行证据中记录，至多重试一次，不产生中间 BLOCKED、不释放执行占用、不改变焦点。
只有最终结果触发 DONE 或 BLOCKED。TASK_SPEC_FAIL / BLOCKED 不重试。每次尝试均保留报告及重试决定。
MK 在执行期间请求 BLOCKED / DEFERRED 时，先记录停止意图，保持 RUNNING；当前同步执行返回或超时后才释放占用，并禁止后续重试。
这是等待当前进程退出的停止方式，不承诺 MK 命令立即强杀进程。异常中断留下的占用需人工核查，不能凭时间戳自动释放。

原子任务启动必须是当前焦点阶段的直接子节点；同一时刻最多一个原子任务 RUNNING。
DONE 后焦点自动返回父节点。下一个原子任务仍须 MK 显式启动；通用状态设置不能启动任务。
失败保留失败节点焦点；跨分支或恢复后继续执行前，由 MK 单独切换到 READY 阶段。
运行占用未结束时拒绝切换焦点。

状态目录与被开发项目、控制仓库相互分离。history/ 的事件文件只追加，记录操作者、审计时间、命令、依据、前后状态及哈希链。
map.json、findings.json 是可重建快照，历史是状态来源。拒绝请求也记录，业务状态不变。
锁冲突、历史校验失败、版本冲突时拒绝写入。时间戳不参与规则；哈希链可检测变化，不提供针对同用户重写全部历史的不可变存储保证。

提案 Schema 强制包含 questions_for_mk。问题在状态报告中单列；有未决问题的提案不能批准入图。
提示词只要求“需求不明确时列问题，不自行假设”，不指出特定需求的潜在歧义。
控制层不判断问题文本或任务草稿的语义；没有问题字段内容不代表已证明不存在假设。
提案进入 PENDING_MK 后仍不改变地图；批准须匹配提案哈希、当前地图版本，并重新校验引用与图结构。

发现仅进入暂存区。格式错误保留原始消息与错误记录，不推断意图。
MK 删除发现采用墓碑记录，原文和历史保留；提升创建 PENDING 节点，仍不启动任务。

原子任务保护字段必须在 M0 审批前加入；审批后不静默改卡。外部保护资源使用新的 M3 封装，避免改变 M0 的相对路径规则。
真实 Codex Executor 必须附带状态目录拒绝权限和匹配的沙箱实测证明。规划与审查共用只读构造器，不接受可写模式或任意 CLI 参数。
候选 Python 进程仍沿用 M2 观测边界；执行前后复核控制代码与状态，不把事后检测说成 OS 阻止。

控制层命令入口为 python -m coding_agent.m3_run：demo（无模型脚本演示）、prepare（生成待确认规划请求）、execute（执行已逐次批准的请求）、mk（带依据和地图版本的显式操作）、report（确定性报告）。
真实规划最多五次，每次调用前单独确认完整请求。准备请求、测试和沙箱探测均不调用模型。
