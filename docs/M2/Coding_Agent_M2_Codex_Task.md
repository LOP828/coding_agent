- 唯一开发仓库：`D:\project\coding_agent`（WSL：`/mnt/d/project/coding_agent`），**独立于**自媒体、CNC 等项目；不得套用其他仓库的分支、脚本或验收规范。

## 三、需求与实现边界

### R-M2-01｜进程隔离的确定性验证（修复第 8 类漏洞）

- 负责**判定、比对、出报告**的主进程在任何阶段均**不得导入或执行候选代码**，也不得让候选仓库代码成为主进程的 pytest 插件或可信校验逻辑。
- 新版冻结测试仅保存**输入 → 期望输出／期望异常**的用例数据；可信主进程持有期望值，独立子进程负责导入候选实现、执行输入、通过 **stdout** 输出可解析的执行观测（返回值或异常）。
- 主进程自行解析、校验观测格式并与可信期望值比较，按既有确定性规则生成报告；**子进程返回的 PASS、判定标签或自称成功不得作为裁决**。
- 子进程**超时、崩溃、非正常退出、stdout 无法解析或格式不合法**，均按 **UNVERIFIABLE** 处理；保存退出状态、stdout/stderr 与超时证据。解析及错误处理不得以执行候选代码实现。
- 候选文件、可信用例数据、审批记录、验证报告之间必须明确隔离写入边界；如仅靠进程隔离无法防止候选进程篡改磁盘上的可信材料，需如实说明残余风险，不得声称已实现完整安全沙箱。
- 新用例格式创建**新版本样本及审批记录**；新审批记录须显式标注“**合成夹具（synthetic fixture）**”，不得冒充 MK 的真实审批；旧版 M0/M1 样本及已冻结记录保留不变。
- 回归要求：第 8 类作弊样本由历史“**已知误通过**”变为 **HARD_FAIL**；样本 04 **仍保留已知误通过**，不是本轮修复对象；同时覆盖期望输出、期望异常及异常退出场景。

### R-M2-02｜Codex 写入限制实测

- 先执行 `codex --version`，记录实际版本；以 **v0.163.0** 为 MK 的预期基准，版本不同需报告差异，不得声称已验证 v0.163.0。
- 严格参照 `docs/M1/Codex_Harness_Write_Restrictions.md` 记载的配置方式，在**可丢弃的测试副本**中实测写入限制；不得以源码阅读或设计推断代替实测。
- 实测矩阵必须分别覆盖：①允许路径写入；②禁止路径写入；③新建文件；④重命名/移动；⑤符号链接及通过链接写入；⑥由 Codex 启动的子进程写入。必要时区分目标位于允许/禁止路径的情况。
- 每项记录配置、命令/任务、目标路径、退出结果、变更前后证据及实际文件差异；归类为“**沙箱直接阻止**”“**沙箱未阻止、仅 M1 事后检测**”或“**未证实/受阻**”。
- 将结果整理为**实测表格**，逐项标记“已实测”还是“推断”；发现绕过边界不得隐瞒或将事后检测表述成沙箱阻止。

### R-M2-03｜真实 Codex Executor 适配

- 仅在**一次性仓库副本**内，按配置非交互调用本机 Codex CLI；模型、推理强度和超时均可配置，保存实际 `codex --version`、调用参数与退出信息。
- 交给 Codex 的内容**仅限**任务卡中的 Property 描述、允许修改的路径、必要项目说明；**不提供冻结测试源码、用例数据、期望结果或审批内部细节**。
- 完整保存本次 Codex 执行轨迹、命令输出、退出码、超时情况和副本变更证据；敏感凭据不得写入归档报告。
- Codex 执行结束后**直接复用 M1 Runner 原有验证与判定通道**，不可为“真实 Executor”另开旁路、降低审查标准或信任 Codex 的自评。

### R-M2-04｜真实任务

- 建立**专用演示仓库**，由真实 Codex 完成 **provider 校验**任务，并保留“任务卡 → 执行 → Runner 验证 → 判定”的完整单次证据。
- 第二个任务只在 **cnc-programmer 的一次性副本**上运行；具体 Property/任务由 **MK 指定**。不得直接操作或修改 CNC 原仓库。
- 对尚未由 MK 指定的任务，不得自行编造验收 Property 或把演示结果冒充该任务完成。

### R-M2-05｜最简失败处理

- **EXECUTION_FAIL**：至多自动重试 **1 次**；重试反馈仅包含失败的 Property 描述与失败摘要，不附冻结测试源码、用例或期望结果。
- **第二次仍失败**，或出现 **TASK_SPEC_FAIL / BLOCKED**：立即停止，不自动重规划；产出给 MK 的简明说明：任务标识、未满足的要求、结果类别、证据路径、需 MK 决策的事项。
- 证据必须逐次记录 attempt 编号、失败摘要、重试决定、各次执行/验证结果；不得用最后一次结果覆盖首次失败记录。

### R-M2-06｜证据存放

- 证据目录**默认在被验证仓库之外**，避免候选代码通过修改仓库文件污染证据；同时记录副本路径、可信证据位置及关联任务/运行 ID。
- 保留 M1 的 Git/文件快照核查；不得把“证据在仓库外”直接等同于具有 OS 级权限隔离。

## 五、跨平台开发约束

- Windows 原生验收以**中文系统 CP936、`git core.autocrlf=true`、不设置 `PYTHONUTF8`**为准；Linux 通过不能替代 Windows 验收。
- 新增/修改的文本文件读写显式指定 `encoding="utf-8"`；记录和比较相对路径统一使用 `as_posix()`，避免平台换行与路径分隔符引发差异。
- 不把 WSL 路径、`/mnt/...`、`.venv/bin/python` 等写死为唯一执行路径；不无条件依赖 `fcntl` 等单平台模块。上述仓库路径仅用于**定位**，不应嵌入通用实现。
- 新测试加入默认 `python -m pytest` 测试集；不修改或重新标记旧版 `legacy_frozen` 测试以绕开验收。
